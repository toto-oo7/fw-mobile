# 小浮窗独立账号 · 管理员配置

本地 b19 已包含账号界面。完成以下配置后再发布，空配置不会开放注册。

## 1. Supabase 项目

在 https://supabase.com/dashboard 创建项目。数据库密码由管理员自己设置和保管，不写入网页。

在 SQL Editor 运行同目录的 `setup.sql`。脚本创建 `fw_records` 表、按账号限制访问的 RLS 策略，以及事务合并函数 `fw_merge_records`。

在项目的 Connect / API Keys 中取得：

- Project URL（例如 `https://项目引用.supabase.co`）
- Publishable key（以 `sb_publishable_` 开头，允许用于公开网页）

填写根目录 `cloud-config.js` 的 `url` 和 `publishableKey`。不要使用 `sb_secret_`、`service_role`、数据库密码或用户密码。

## 2. 邮箱账号

Authentication → Sign In / Providers：启用 Email 注册，保持 Confirm email 开启，密码最小长度至少 8 位。

Authentication → URL Configuration：

- Site URL：`https://toto-oo7.github.io/fw-mobile/`
- Redirect URLs：添加同一个完整地址，不使用任意域名通配符。

Authentication → Email / SMTP Settings：配置自己的 SMTP 发信服务。Supabase 默认邮件仅面向项目团队成员，不能用于普通朋友注册。用服务商验证过的发件地址，发信密码只保存到 Supabase 控制台。

保留确认注册和重置密码邮件模板中的官方链接。用户确认邮箱后可回到主屏幕 App 输入邮箱和密码登录；重置链接会打开网页中的“设置新密码”。

## 3. 发布及验收

发布生产源码、同目录的 supabase.js、字体及许可证，不上传个人 JSON、PAT、任何 service_role 密钥。原 GitHub 同步继续在未登录的本机空间使用。

正式邀请朋友前需用管理员自己的两个临时账号核对：A 的待办不会出现在 B；退出、重新登录仍能恢复内容；第二台设备能同步；断网改动联网能上传；确认和重置邮件可送达；未登录及 B 的令牌无法读取或修改 A 的数据库记录。当前尚未执行真实云端验收。

不要把自己原来的备份发给朋友。自己的旧数据可在本机空间导出，登录自己的邮箱账号后导入；导入会覆盖当前账号本机内容并参加后续同步。Windows 端尚未接入邮箱账号同步，需要继续使用原 GitHub 通道或另外适配。

## 4. 告诉朋友怎样安装

用 iPhone Safari 打开 `https://toto-oo7.github.io/fw-mobile/` → 分享 → 添加到主屏幕 → 添加。从主屏幕打开 → 设置 → 登录 / 注册。

需使用自己的邮箱、密码；先确认注册邮件。不同账号在浏览器本地和云端分别保存数据。退出不会删除尚未同步的本机账号缓存，请在自己的设备上使用。删除云端账号由管理员在确认本人请求后通过 Supabase 管理，不提供客户端管理员密钥。
